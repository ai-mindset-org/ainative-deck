// SOURCE MAP

агенту нужны источники до запроса

Для вашего процесса: где уже лежит правда? Выберите 3 источника – не десять. У каждого: почему важен и как агент до него дотянется.

  • chat / переписка – решения и договорённости
  • transcripts – звонки, голосовые
  • docs / notes – документы, база знаний
  • calendar – ритм и дедлайны
  • tasks – трекер, тикеты
## source map — шаблон - source: транскрипты созвонов why: там живут реальные решения access: папка transcripts/ в vault - source: рабочий чат why: статусы и блокеры access: экспорт / MCP - source: задачник why: что уже решено делать access: API / выгрузка
// NAMING + FILES

имя файла – это база данных

Файл, который нельзя найти повторно, не существует. Одна конвенция решает: поиск, сортировку по дате, понимание без открытия.

# шаблон {project} {type} description – YYYY-MM-DD.md # примеры {crm} {meeting} weekly sync – 2026-07-14.md {lab} {research} competitors scan – 2026-07-14.md {ops} {process} invoice flow – 2026-07-14.md
  • дата в конце – сортировка бесплатно
  • тип в скобках – агент фильтрует по типу без чтения
  • имя латиницей – стабильные ссылки, git, шаринг
// ФАЙЛЫ ПРАВИЛ

среда начинается с правил, не с промпта

AGENTS.md / CLAUDE.md – файл, который агент читает до вашего первого сообщения. Иерархия: глобальный (кто вы, стиль) → проектный (эта задача, эти границы).

  • роль и контекст – кто вы, что за проект
  • правила – нейминг, язык, что нельзя
  • карта – где что лежит, куда писать

факт: правила читаются в каждой сессии – файл держите коротким, до ~200 строк. дальше модель начинает терять инструкции.

# AGENTS.md — минимум ## кто я руковожу X, процесс – Y ## правила - файлы: {project} {type} desc – date - отвечай кратко, по-русски - не трогай папку private/ ## карта - источники: sources/ - результаты: output/ - журнал запусков: log.md
// CONTEXT PACK

паспорт задачи – переносит её между запусками

Context pack – одна карточка, из которой любой агент (и вы через месяц) понимает задачу без пересказа. Это answer на главный вопрос занятия.

  • goal – что должно получиться
  • current state – где мы сейчас
  • rules – критерии качества от M1
  • examples – 1-2 образца «как хорошо»
  • boundary – что агенту нельзя
# context pack — заполните свой goal: еженедельный дайджест проекта current: пишу руками 2 часа по пятницам rules: ≤1 страницы, факты со ссылками, без воды, структура: сделано/риски/дальше examples: digest-2026-07-04.md (эталон) boundary: не отправлять без моего ок, не использовать приватные заметки
// SKILL

skill = текст повторяемого действия

Папка + файл SKILL.md. Агент видит имя и описание всегда, тело – когда триггер сработал. Один skill = одна процедура.

данные: скиллы, курируемые человеком из своей практики, дают +16 п.п. к качеству прогона; сгенерированные пачкой «на всякий случай» – ноль. skill рождается из повторения, не из фантазии.

# ~/.claude/skills/weekly-digest/SKILL.md --- name: weekly-digest description: Use when просят «собери дайджест недели» по проекту X. --- ## шаги 1. прочитай log.md + transcripts/ за 7 дней 2. собери: сделано / риски / дальше 3. проверь против examples/digest-эталон 4. сохрани в output/digest – {date}.md ## evidence файл существует · ≤1 стр · есть ссылки

// FIRST RUN

первый запуск должен дать артефакт

Не «поговорить с агентом», а получить файл. Критерий: после первого прогона в папке output/ лежит то, что можно открыть и оценить против правил из context pack.

# мини-промпт первого запуска прочитай AGENTS.md и context-pack.md. собери {выход процесса} по шагам из skill. перед сохранением сверь с examples/ и rules. результат → output/{имя по конвенции}.md в конце: 3 строки – что сделал, что не смог, что уточнить.

live demo: собираю skill под процесс участника и запускаю

// EVIDENCE

результат возвращается в систему

output
файл-артефакт
→
evidence
оценка против правил: прошёл / нет / почему
→
update
правка skill или context pack
↺

То, что вчера у Стёпы называлось «сверка рекомендовано ↔ стало» на уровне организации – у вас происходит на уровне одного процесса: каждый прогон делает следующий лучше. Правки – тоже данные.

  • evidence – это файл, не ощущение: строка в log.md
  • 2 из 3 действий агента мимо ожиданий = мало контекста, чините pack
  • 3 ручные правки одного и того же = место для нового правила в AGENTS.md
// BOUNDARIES

автономия начинается с границ

public

можно наружу

публикуемые артефакты, обезличенные примеры. агент действует сам.

team

внутри команды

рабочие документы, транскрипты командных встреч. агент действует, человек видит.

local

только у меня

личные заметки, черновики, финансы. не покидает устройство – никаких облачных индексов.

ask first

спроси до

отправка людям, удаление, деньги, публикация. агент готовит – человек нажимает.

В чат лабы: скриншот или sanitized-фрагмент, не сырые приватные файлы. Токены и ключи – только в localStorage/env, никогда в файлах репозитория.

// THREE INTERFACES

интерфейс выбирается по человеку, принцип один

terminal-first

claude code

максимум контроля: скиллы, субагенты, хуки. если вы живёте в терминале – ваш вход здесь.

parallel-tasks

codex

облачные задачи параллельно, песочницы, ревью диффов. сильный на «сделай N вещей, покажи что вышло».

editor-first

cursor / cowork

агент внутри редактора: видишь файлы, правишь рядом. мягкий вход, тот же AGENTS.md.

tool-FOMO выключаем: файлы правил, скиллы и context pack переносимы. среда – ваша, рантайм – сменный.
// PERSONAL → TEAM

личная система становится командной через протокол

personal OS
мои правила · мои скиллы · мой vault
→
shared protocol
общий git: нейминг · SSOT скиллов · зеркала
→
team workflow
общая память: commit = запись, blame = кто и когда

Перелом 2→3 из матрицы. Ничего нового не покупается: тот же markdown, тот же git. Меняется одно – у файлов появляется второй читатель, и правила из «моих привычек» становятся протоколом.

пример из нашей команды: скиллы живут в одном репозитории-SSOT, скрипт разливает их по 5 зеркалам; полный контур – к лекции Димы про трансформацию (15.07).

руками: ваш baseline

  • 1. процесс из M1 – одной строкой
  • 2. source map – 3 источника: why + access
  • 3. context pack – 5 полей
  • 4. skill skeleton – триггер · шаги · output · evidence
  • 5. boundary – что агенту нельзя

шаблон – в чате лабы и на LMS. потом 2–3 разбора добровольцев: чиним границы и evidence.

# {project} {context} one workflow seed – 2026-07-14 ## workflow ## source map - source: · why: · access: ## context pack - goal: · current: · rules: - examples: · boundary: ## first skill - trigger: · steps: · output: · evidence: ## next run - when: · what to review:
