Слой 1 — детали

Инфраструктура

3 типа данных

  • Внутренние БД — Postgres, ClickHouse, SQLite
  • SaaS-системы — Gmail, Slack, Notion, CRM
  • Потоковые — метрики, клики, звонки, Telegram

Единая шина вместо прямого подключения каждого агента к каждому источнику. Один клиент может быть в 10 несвязанных системах.

Gateway — 6 функций

  • Аутентификация и авторизация (SSO, corp tokens)
  • Ролевой доступ (RBAC по моделям и инструментам)
  • Бюджетирование (квоты TPS/RPM, soft/hard limit)
  • DLP — маскировка PII перед отправкой в API
  • Policy Engine — Allow / Redact / Reroute / Block
  • Аудит — полное логирование для compliance

Guardrails

Не промпт-контроль, а анализ команд перед исполнением. Проверяет: соответствие политике, промпт-инжекшн, секреты/PII, разрешённость инструментов.

Принцип: «запрещено всё, что не разрешено» (корпоративная среда) vs «разрешено всё, спрашивай в сомнительных» (личная)

NemoGuardrails (NVIDIA), Claude Code settings.json (allow/deny per MCP)

Model routing

Haiku vs Opus = 60x разница в цене. Роутинг на уровне скилла: поле model в skill.md, не динамическая классификация запроса.

70-80% запросов → Flash/Haiku/GPT-4o mini ($0.25/1M tokens)
20-30% → Opus/Sonnet/GPT-4.5 ($15/1M tokens)

Простой промпт
подключи MCP для Notion к Claude Code. покажи settings.json с правами: читать — всегда, писать — спрашивать
Продвинутый промпт
у меня компания [опиши]. настрой: 1. MCP-серверы: Notion/Slack/Gmail/Calendar 2. settings.json: читать — всегда, писать — спрашивать, удалять — никогда 3. guardrails: запретить PII в API (маскировка) 4. роутинг: грамматика → Haiku, ресёрч → Opus 5. DLP: маскировка имён, номеров, сумм 6. аудит: event_time, user_id, model, cost 7. лимиты: квоты токенов по сотрудникам 8. policy: Allow / Redact / Reroute / Block

Слой 2 — детали

Данные, онтология и контекст

Контекст-инжиниринг vs промпт-инжиниринг

Промпт-инжиниринг — что вы говорите модели. Одна инструкция, влияет на задачу.

Контекст-инжиниринг — что модель видит при принятии решения. Данные, память, context window. Влияет на процесс.

90-мин транскрипт = 15,000 токенов каждый раз, когда агенту нужен один факт. Граф контекста парсит один раз, хранит структурно, отвечает за ~5ms.

Структура папок Степана

context/ calls/ ← ~600 звонков + index.md emails/ telegram/ sessions/ ← логи каждой сессии Claude styles/ content/ ← артефакты агентов projects/ aim-lab/ deals/ ← инвестиционные сделки

SQLite граф контекста

Ежедневный скрипт: читает все новые звонки/Telegram/имейлы. Извлекает: решения, действия, сделки, коммитменты, метрики. Каждый факт — с прямой цитатой и ссылкой.

entity, type, value, source, timestamp, confidence

Финальная цель: компания как граф токенов. Каждое слово на звонке → автоматически в граф контекста в реальном времени.

QMD vs RAG

QMD — open-source, гибридный поиск (BM25 + векторный + LLM). Точнее, чем чистый RAG.

Для компании 1-50: Entity resolution, context directory в Git, CLAUDE.md, SuperMemory/ZEP
50-300: + Glean Enterprise Graph, Neo4j/FalkorDB, Zep bi-temporal tracking

Простой промпт
создай структуру папок для моих данных: context/ (calls/, emails/, sessions/), content/, projects/. напиши CLAUDE.md с описанием что где лежит
Продвинутый промпт
создай систему контекста: 1. структура: context/ (calls/, emails/, telegram/, sessions/), content/, projects/ 2. index.md в каждой папке — обновляется автоматически 3. скрипт индексации: извлечь решения, action items, метрики 4. каждый факт с цитатой и ссылкой на источник 5. decay: факты > 90 дней — confidence < 0.5 6. entity resolution: связать людей из разных систем 7. формат: SQLite (entity, type, value, source, timestamp, confidence) 8. CLAUDE.md как точка входа для всех агентов

Оркестрация

4 типа агентов

  • Регулярный (cron) — живёт на сервере, просыпается по расписанию. OpenClaw: ночью читает Twitter, в 9 утра дайджест в Telegram
  • По запросу (on-demand) — по команде: «сделай презентацию», «напиши мемо»
  • Событийный (event-driven) — включается по триггеру. Трамп объявил — workflow запустился
  • Зеркальный (mirror) — агент Алисы общается с агентом Бориса, эскалируют только важное

5 топологий оркестрации

  • Sequential — A → B → C. Линейные задачи
  • Parallel — A → [B,C,D] → E. Ресёрч по акции: 4 агента параллельно
  • Group Chat — агенты пишут в общий контекст. Диалектика: тезис-антитезис-синтез
  • Business Process — граф с ветвлением и условиями. Customer support
  • Hybrid — скрипты, внешние сервисы, human-in-the-loop

Research agent — 3 уровня

Быстрый → 1 агент
Стандартный → 2-3 субагента
Глубокий → 3-5 + Quality Reviewer

Multi-agent создаётся тремя строчками текста в skill.md. Проблема не в создании, а в том, чтобы работало в масштабе — это требует 50+ итераций.

Generator-Discriminator

5 судей × 3 круга × ~40 мин

Параметры: свежесть данных, практичность, релевантность фокусу, язык, полнота. Цена: дорого по токенам. Результат: значительно лучше ручной работы.

Production: Moti / Inngest / Temporal — retry, checkpoint, дедупликация

Простой промпт
напиши skill.md для research-агента: при запросе «исследуй [тему]» запусти 3 субагента параллельно (компания, технология, рынок), собери результаты в один отчёт
Продвинутый промпт
создай research-агент: 1. 4 субагента параллельно: компания, технология, рынок, контекст 2. quality reviewer: 5 параметров (свежесть, практичность, релевантность, язык, полнота) 3. три круга итераций generator-discriminator 4. финальный markdown с executive summary 5. лог: время, токены, стоимость каждого субагента 6. если стоимость > $2 — предупреди 7. напиши skill.md файл целиком

Скиллы и Workflow

Скиллы = процедурная память

Не жёсткие инструкции, а пространство для принятия решений. Описывают «как делать работу», не факты.

TDD для скиллов: сначала пишешь eval (что хочу получить), потом делаешь скилл. Eval before skill.

Marketplace скиллов

Приватный GitHub репозиторий для команды: версии, fork, дистрибуция. Автор скилла — эксперт в своей области (не CEO).

Последний шаг каждого скилла у Степана — сохранить лог сессии: время, задача, ошибки, какие MCP вызывались.

Метрики скиллов

  • Adoption rate — сколько сотрудников используют, как часто возвращаются
  • Глубина сессии — сколько правок требует агент (меньше = лучше)
  • NPS — в конце скилла: «оцени от 1 до 9»
  • Процент завершённых задач / кол-во рестартов
  • Стоимость — цена workflow vs экономия времени
  • Latency — время от запроса до результата

Observability

LangFuse — трейсинг, аналитика, время/порядок вызовов MCP

Eris.com — платформа для логирования и трекинга метрик агентов

AB-тестирование скиллов: всегда версионировать, хранить несколько версий, прогонять обе через evals (аналог catastrophic forgetting при fine-tuning)

Простой промпт
напиши eval для моего [research] скилла: 3 критерия pass/fail. прогони скилл и покажи результат по каждому критерию
Продвинутый промпт
создай систему evals для скиллов: 1. unit test: каждый шаг — критерии pass/fail 2. integration test: полный процесс end-to-end 3. business metric: время, стоимость, качество 4. NPS в конце (1-9), запись в лог 5. AB-тест: 2 версии, прогнать обе через eval 6. catastrophic forgetting: новая не хуже старой 7. трассировка: MCP вызовы, ошибки, latency 8. dashboard: adoption, глубина, стоимость

Организация и люди

AI Champion

Обычный сотрудник внутри компании, не нанятый консультант. Citibank — 4000 человек.

Задачи: находить кейсы, объяснять коллегам, формулировать стратегию по своей функции. Кейсы — только децентрализованно (нужны доменные знания).

Компилятор людей

Скилл, который берёт глубокое интервью у человека о его работе (15 вопросов) и генерирует skill.md на основе ответов.

40-60% операционных эвристик извлекаются только через LLM-интервью, не через документацию (arxiv.org/html/2507.03811v1)

4 роли, которые остаются за человеком

  • Архитектура — проектирование системы
  • Отношения — эмпатия, переговоры, мотивация
  • Валидация — проверка результатов агента
  • Ответственность — принятие решений

Парадоксы

50% сотрудников норвежского суверенного фонда генерируют код — без обучения программированию.

Парадокс: рабочий день после подключения AI-инструментов увеличивается ~в 2 раза (HBR). Найм: «докажи, что нельзя сделать с AI». Саботаж: 88% организаций сообщали об инцидентах.

Простой промпт
проведи со мной интервью о моей работе (10 вопросов) и сгенерируй skill.md на основе ответов. добавь секцию «когда эскалировать человеку»
Продвинутый промпт
проведи «компилятор людей» — 15 вопросов: 1-5: что делаешь, что повторяется, где время 6-10: какие данные, с кем коммуницируешь, ошибки 11-15: как обучаешь новых, метрики, если AI делает — что он должен знать по ответам: skill.md + eval (5 критериев pass/fail) + секция эскалации + типичные ошибки + 4 роли человека: архитектура, отношения, валидация, ответственность

Governance

Бюджет конкурирует с ФОТ

AI-бюджет конкурирует с ФОТ, не только с расходами на ПО. $250K/год (Jensen Huang, NVIDIA) — не универсально. Главный совет: начать измерять и искать корреляцию с результатами.

Классическая фирма: 70 сотрудников, 5 уровней, $4.2M/год ФОТ → AI-native фирма: 10 сотрудников + агенты, $600K/год ФОТ. ~85% сокращение.

4 уровня компетенций (Ramp)

  • Не-пользователь — не работает с AI
  • Пользователь — ChatGPT, Claude, Codex
  • Нетехнический билдер — создаёт скиллы, workflow
  • AI builder — архитектура, оркестрация, evals

Трекинг токенов

Трекинг токенов по сотрудникам — метрика внедрения. Еженедельные встречи/канал где люди делятся находками.

FINRA: chain-of-thought как compliance документация. Логика рассуждения LLM — документация для регуляторных целей.

Коллегиальность

«Мы не инженерим AI — мы его открываем. Это процесс первооткрывания, как физика. Квантовая теория поля существует, но её нужно открыть.»

OKR = цели агента, стендапы = статус-чеки, регламенты = спеки и скиллы, peer review = GAN, оргструктура = граф оркестрации, performance review = evals

Простой промпт
настрой логирование: каждый скилл в конце записывает лог (время, задача, ошибки, стоимость). добавь алерт при >$5 за сессию
Продвинутый промпт
создай governance для AI в компании: 1. бюджет: лимиты токенов по сотрудникам/отделам 2. аудит: все LLM-вызовы (кто, модель, токены, $) 3. DLP: маскировка PII (имена → [PERSON]) 4. метрики: adoption, частота, ROI по задачам 5. compliance: chain-of-thought как документация (FINRA) 6. еженедельный отчёт: использование + аномалии 7. 4 уровня компетенций: классифицировать сотрудников 8. emergency: auto-switch на дешёвую модель

Токен-экономика

Каждый процесс — это поток токенов

Три типа блоков

  • Автомат — AI делает без участия человека
  • Ревью — AI делает, человек проверяет
  • Человек — только человек

Зачем это нужно

  • Видеть узкие места — где человек тормозит
  • Считать стоимость — токены vs часы
  • Планировать автоматизацию — что делегировать первым
  • Измерять прогресс — % автономности

Формула: стоимость процесса = (токены × цена модели) + (часы человека × ставка)

Цель: переводить красные блоки в жёлтые, а жёлтые в бирюзовые

Память AI

3 типа памяти

Эпизодическая

Что происходило — звонки, встречи, сообщения. Причинно-следственные события с хронологией.

клиент пришёл → попробовал → отказался → дали скидку → купил. порядок важен. ZEP хранит хронологию. без неё агент не поймёт контекст скидки
создай context/calls/ и напиши скрипт ежедневной индексации: 1. из новых звонков извлечь решения, action items, коммитменты, метрики 2. каждый факт с прямой цитатой и ссылкой на источник 3. факты старше 90 дней — confidence score < 0.5 4. формат: entity, type, value, source, timestamp, confidence 5. при добавлении звонка — обновить index.md 6. Named Entity Recognition: решения, сделки, суммы, дедлайны 7. сохранять причинно-следственные связи: "клиент отказался → дали скидку → купил" 8. ZEP bi-temporal: когда факт стал известен vs когда произошёл

Семантическая

Факты и знания — LLM силён по умолчанию (pre-train). Но: ваши данные он не знает.

Claude знает что Python — язык программирования. но НЕ знает что ваш клиент Иванов предпочитает созвоны по вторникам. CLAUDE.md и контекст-граф — это семантическая память компании
проанализируй мои последние 20 чатов и извлеки повторяющиеся инструкции: 1. оформи как правила в CLAUDE.md 2. группируй по: форматирование, процессы, инструменты, запреты 3. для каждого правила — укажи источник (из какого чата) 4. приоритизируй: чаще повторяется = выше 5. добавь секцию "контекст компании": кто мы, что делаем, какие инструменты 6. добавь секцию "стиль": как пишем, какие слова используем/не используем 7. проверь противоречия между правилами 8. предложи structure для CLAUDE.md (секции, порядок)

Процедурная

Навыки и процедуры — skills, workflows. Должностные инструкции агента.

skill.md = должностная инструкция. не «ответь на вопрос», а «сначала проверь CRM, потом звонки, потом напиши ответ в формате X». пространство для решений, не жёсткий скрипт
проведи со мной интервью о процессе [задача]: 1. задай 15 вопросов: что делаешь каждый день, какие задачи повторяются 2. где тратишь время, какие решения принимаешь, на основе чего 3. какие данные нужны, где лежат, с кем коммуницируешь 4. что бы делегировал, какой идеальный результат 5. какие исключения бывают, как обрабатываешь ошибки 6. по ответам сгенерируй skill.md с eval-критериями 7. добавь секцию "когда эскалировать человеку" 8. добавь секцию "типичные ошибки и как их избежать" 9. в конце — eval: 5 критериев pass/fail для этого скилла

Качество

"Evals are the new PRD"

Принцип TDD для скиллов

  • Сначала eval (что хочу получить), потом skill
  • Binary pass/fail — никаких шкал 1–5
  • 5 параметров: свежесть данных, практичность, релевантность, язык, полнота
  • Три круга итераций generator-discriminator

Операционные метрики

  • Adoption rate — сколько сотрудников используют
  • Глубина сессии — сколько правок требует агент
  • NPS — спрашивать в конце скилла (1–9)
  • Стоимость — цена workflow vs экономия времени
  • AB-тестирование: 2 версии скилла через eval
Пример eval: research-skill v1.2
Критерии (pass/fail):
1. релевантность: результат связан с моим бизнесом, не абстрактный
2. свежесть: все данные < 6 месяцев
3. источники: каждое утверждение имеет ссылку
4. практичность: можно действовать на основе результата
