// NAMING · САМАЯ ГЛАВНАЯ ШТУКА, С КОТОРОЙ МОЖНО НАЧАТЬ

имя файла –
это база данных

Файл, который нельзя найти повторно, не существует. «Если заберёте одно – заберите naming convention». И не создавайте файлы сами – дайте правила агентам. Отсутствие культуры – это отсутствие правил нейминга.

# шаблон {project} {type} description – YYYY-MM-DD.md # примеры {crm} {meeting} weekly sync – 2026-07-14.md {lab} {research} competitors scan – 2026-07-14.md {ops} {process} invoice flow – 2026-07-14.md # дата в конце → сортировка бесплатно # тип в скобках → агент фильтрует без чтения # среднее тире –, имя латиницей
// ФАЙЛЫ ПРАВИЛ · СРЕДА НАЧИНАЕТСЯ НЕ С ПРОМПТА
# AGENTS.md – минимум ## кто я руковожу X, процесс – Y ## правила - файлы: {project} {type} desc – date - отвечай кратко, по-русски - не трогай папку private/ ## карта - источники: sources/ - результаты: output/ - журнал: log.md

rule живёт
дольше промпта

AGENTS.md / CLAUDE.md – файл, который агент читает до твоего первого сообщения. Rule – эвергрин-промпт, который пополняется и живёт; эта сущность была у нас ещё до того, как Anthropic принесла абстракцию skill.

факт: правила читаются в каждой сессии – держи файл до ~200 строк, дальше модель теряет инструкции

// CONTEXT PACK · ПАСПОРТ ЗАДАЧИ

паспорт задачи

Одна карточка, из которой любой агент (и ты через месяц) понимает задачу без пересказа. Это ответ на главный вопрос занятия.

  • goal – что должно получиться
  • current – где мы сейчас
  • rules – критерии качества из M1
  • examples – 1–2 образца «как хорошо»
  • boundary – что агенту нельзя
# context pack goal: еженедельный дайджест проекта current: пишу руками 2ч по пятницам rules: ≤1 стр · факты со ссылками структура: сделано / риски / дальше examples: digest-2026-07-04.md boundary: не отправлять без ок не брать приватные заметки
// SKILL · ОТЧУЖДЁННАЯ ПРОЦЕДУРА
# ~/.claude/skills/weekly-digest/SKILL.md --- name: weekly-digest description: Use when просят «собери дайджест недели» по проекту X. --- ## шаги 1. прочитай log.md + transcripts/ 7 дней 2. собери: сделано / риски / дальше 3. сверь с examples/digest-эталон 4. сохрани в output/digest – {date}.md ## evidence файл есть · ≤1 стр · есть ссылки

skill = текст
повторяемого действия

Папка + SKILL.md. Имя и описание агент видит всегда, тело – когда триггер сработал. Skill рождается из третьего повтора, не из фантазии.

данные: скиллы из своей практики дают +16 п.п. качества; нагенерённые пачкой – ноль

// EVIDENCE · СЛЕД, КОТОРЫЙ ЗАМЫКАЕТ КОНТУР

контур закрыт,
когда есть след

Первый прогон – диагностика, не финал. Результат возвращается в систему: output → evidence → правка skill. Это «сверка рекомендовано ↔ стало» Стёпы, но на одном процессе.

  • «что нельзя измерить, нельзя улучшить» – критерии до прогона
  • evidence – это файл, не ощущение: строка в log.md
  • 2 из 3 действий мимо = мало контекста, чини pack
  • без ревью не continuous improvement, а continuous degradation – дёргаешь рычаг, а хуже
  • ответственность – единственное, что не переходит агенту
