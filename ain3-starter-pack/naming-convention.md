# Naming convention – самая главная штука, с которой можно начать

Файл, который нельзя найти повторно, не существует. Одна конвенция даёт и человеку, и агенту опору: куда идти, что это, когда сделано. Навигация – это нейминг, а не глубокие папки.

## Шаблон

```
{project} {type} description – YYYY-MM-DD.md
```

- **{project}** – короткий slug проекта/процесса: `crm`, `lab`, `ops`, `sales`
- **{type}** – тип в фигурных скобках: `{meeting} {research} {process} {guide} {analysis} {draft}`
- **description** – на латинице, 2–5 слов
- **дата в конце** – `YYYY-MM-DD`, всегда после тире → сортировка бесплатно
- **тире** – только среднее (–), U+2013. Не длинное тире, не дефис, не минус

## Примеры

```
{crm} {meeting} weekly sync – 2026-07-14.md
{lab} {research} competitors scan – 2026-07-14.md
{ops} {process} invoice flow – 2026-07-14.md
{sales} {draft} outreach batch 2 – 2026-07-14.md
```

## Два правила поверх

1. **Файлы называет агент, не ты.** Правило живёт в `CLAUDE.md` / `AGENTS.md`, а не в головах людей. Не надо приучать команду к разметке – за это отвечает файл правил.
2. **Дата никогда не в середине.** `2026-07-14 report.md` ломает сортировку по типу; `{ops} {report} … – 2026-07-14.md` – нет.

## Почему это работает

Тип в скобках → агент фильтрует по типу без чтения содержимого. Дата в конце → всё сортируется хронологически. Латиница → стабильные ссылки, git, шаринг наружу без проблем с кодировкой путей. Отсутствие культуры – это отсутствие правил нейминга.
