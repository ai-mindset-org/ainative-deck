# AIN3 · Personal Harness · glossary

> 37 рабочих терминов с коротким определением, ролью и ориентиром по аудитории. `all` – нужен каждому участнику; `operator` – нужен при сборке своего процесса; `dev/ops` – нужен при интеграциях и инфраструктуре.

## База

| Термин | Что это | Зачем в работе | Кому |
|---|---|---|---|
| LLM | Модель, которая продолжает текст и работает с инструкциями, контекстом и инструментами. | Даёт генеративную способность внутри контура. | all |
| Agent | LLM с целью, контекстом, инструментами, правилами и циклом действий. | Выполняет многошаговую работу и оставляет результат. | all |
| AI-native | Способ проектировать процесс с учётом возможностей и ограничений агентов с первого шага. | Помогает пересобрать маршрут целиком. | all |
| Harness | Договорённости и механика вокруг модели: context, rules, tools, review, memory, boundaries. | Направляет модель и делает результат воспроизводимым. | all |
| Artifact | Файл, запись, commit, dashboard или другой наблюдаемый результат. | Даёт адресуeмый output, который можно проверить и продолжить. | all |
| Workflow | Повторяемая последовательность действий от trigger до output и review. | Показывает, где работает человек, агент и connector. | all |

## Контекст и память

| Термин | Что это | Зачем в работе | Кому |
|---|---|---|---|
| Content | Полный объём доступной информации. | Служит сырьём для отбора. | all |
| Context | Маленький достаточный набор информации для текущей задачи. | Уменьшает шум и стоимость прогона. | all |
| Source | Место, откуда агент получает факт или рабочее состояние. | Делает выводы проверяемыми и свежими. | all |
| Source map | Список 3–5 источников с access, freshness и boundary. | Фиксирует минимальный контур входных данных. | operator |
| Context pack | Переносимый срез: goal, current state, rules, examples, boundary, next. | Позволяет начать в новой сессии без длинного чата. | operator |
| Vault | Папка с текстовыми файлами, которую читают человек и агент. | Хранит правила, проекты, решения и evidence. | all |
| Markdown | Простой текстовый формат `.md` с заголовками, списками и ссылками. | Одинаково читается человеком, Git и агентом. | all |
| Memory | Механика сохранения фактов, решений, истории и состояния между запусками. | Поддерживает continuity на разных сроках жизни. | operator |
| Handoff | Короткая передача current state, evidence, blocker и exact next action. | Закрывает сессию и даёт точный restart. | all |
| RAG | Поиск подходящих фрагментов во внешнем хранилище перед ответом модели. | Подмешивает свежие или большие знания в текущий контекст. | dev/ops |
| Graph | Узлы и связи между людьми, понятиями, файлами и событиями. | Помогает видеть маршруты и соседние сущности. | operator |
| Ontology | Договорённость о типах сущностей и отношениях между ними. | Делает граф и данные последовательными. | dev/ops |

## Процедура и качество

| Термин | Что это | Зачем в работе | Кому |
|---|---|---|---|
| Prompt | Инструкция модели в одном конкретном запуске. | Запускает действие в текущем контексте. | all |
| Skill | Сохранённая процедура с trigger, steps, output и checks. | Позволяет повторять способ работы из чистой сессии. | all |
| Router | Корневой `AGENTS.md` или `CLAUDE.md` с картой проекта и правилами. | Загружается до задачи и направляет агента к нужным источникам. | operator |
| Runtime | Среда, где работает агент: Codex, Claude Code, Cursor или другой executor. | Исполняет skill и даёт доступ к tools. | all |
| First run | Первый прогон процесса, который даёт артефакт и диагностирует gaps. | Показывает, чего не хватает в context, rules или skill. | all |
| DoD | Definition of done – проверяемое описание готового результата. | Даёт критериям качества место до запуска. | all |
| Eval | Проверка результата по короткому rubric или набору тестов. | Превращает review в обучающий сигнал. | operator |
| Evidence | Ссылка, diff, receipt, screenshot, test или другой след результата. | Подтверждает, что run состоялся и что изменилось. | all |

## Управление агентами

| Термин | Что это | Зачем в работе | Кому |
|---|---|---|---|
| Boundary | Явная граница read, write, ask first и deny. | Ограничивает доступ и автономию. | all |
| Human-in-the-loop | Точка, где решение, approval или ответственность остаются у человека. | Сохраняет judgment в рискованных действиях. | all |
| Agent Passport | Карточка identity, owner, scope, tools, limits, expiry и revoke. | Делает делегирование видимым и проверяемым. | operator |
| Agent Registry | Единый список агентов, triggers, owners, permissions, last run и status. | Позволяет увидеть, что существует и как остановить. | operator |

## Интеграции и инфраструктура

| Термин | Что это | Зачем в работе | Кому |
|---|---|---|---|
| MCP | Протокол, через который модель вызывает внешние tools и data sources. | Подключает calendar, Telegram, Linear, Krisp и другие системы. | dev/ops |
| API / connector | Программный интерфейс к внешнему сервису. | Даёт read/write access к состоянию за пределами файлов. | dev/ops |
| Git | Система версий для файлов и кода. | Хранит diff, author, history и rollback. | operator |
| Commit | Зафиксированный набор изменений с именем и SHA. | Создаёт адресуемый checkpoint. | operator |
| LMS | Закрытая учебная среда с записями, материалами и progress. | Держит participant-specific контур. | all |
| Dashboard / observability | Поверхность, которая показывает состояние, связи, runs и gaps. | Помогает человеку понять систему и заметить отклонения. | all |
| Overlay | Новый интерфейс поверх существующей системы или сайта. | Добавляет контекст и действие без перестройки legacy-ядра. | operator |

## Минимум для первого дня

Начни с десяти терминов: **artifact · workflow · context · source map · context pack · skill · first run · DoD · evidence · handoff**. Остальные добавляй, когда процесс потребует интеграции, памяти, наблюдаемости или командного управления.
