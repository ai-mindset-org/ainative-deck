# Operating brief – паспорт процесса

Заполни под **один** процесс, который повторяется чаще раза в неделю. Это спецификация, которую можно передать кому угодно – человеку или агенту.

## 5 вопросов

1. **Что запускает процесс?** (триггер: пришло письмо / наступила пятница / появился новый лид)
2. **Входные данные?** (что и откуда: транскрипт звонка, тикеты за неделю, таблица)
3. **Результат?** (что должно появиться на выходе: файл, сообщение, обновлённая запись)
4. **Владелец?** (кто отвечает за процесс – без владельца процесс теряется и мутирует)
5. **Критерий качества?** (definition of done, проверяемый – не «стало лучше»)

## Матрица: кто что делает

Размечай каждый шаг процесса – что берёт агент, что автоматизация, что остаётся человеку.

| шаг | agent | automation | человек (checklist) |
|---|---|---|---|
| собрать входные данные | ✓ | | |
| черновик результата | ✓ | | |
| проверка фактов | | | ✓ проверяю ссылки |
| отправка | | | ✓ нажимаю сам (ask first) |

**Ответственность** – единственное, что никогда не переходит агенту. Handoff (передача человеку) закладывается в процесс до его завершения, а не после провала.

## Первый прогон

Первый прогон – диагностика, не финал. Если 2 из 3 действий агента мимо ожиданий – не хватает контекста, чини карту контекста и критерии, а не промпт.
